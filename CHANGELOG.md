# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Wired in the external **EECO** package (`eeco==0.2.1`, already pinned in `pyproject.toml`) as flex-pse's tariff/operating-cost engine, with the whole integration collected in `flexops/costing/opex.py` — the **sole `eeco` import point** in the codebase (decision R12; a `grep` convention, not an import-linter contract). Public API exported from `flexops.costing`: `load_tariff`/`load_dr_program` (resolve a `tariff_source`/`events_source` to an EECO object; wrap load errors as `FlexDataError`), `tariff_csv_to_dict` (EECO `rate_data` CSV **or** pre-loaded DataFrame → the dict `load_tariff` accepts, with optional `write_to=` JSON persistence), the pandas signal helpers `price_series`/`is_peak`/`peak_windows`/`price_gradient` (flex-pse helpers over EECO's `get_charge_dict` charge arrays, for logic/heuristic constraints), the in-objective Pyomo bridges `add_operating_cost`/`add_gas_cost` returning `OperatingCostHandles` (EECO builds the **convex-relaxed** cost `Expression`s via `costs.calculate_itemized_cost`; the wrapper only renames outputs and asserts the demand charge stayed a linear epigraph — the built model classifies **LP**), the post-optimization evaluators `evaluate_cost`/`evaluate_gas_cost` (the TRUE de-relaxed bill on a fixed realized numpy array — the user-facing number, R4/R9; `evaluate_cost` reproduces a hand-computed PG&E-B-20-flavored monthly bill to the cent, $14,085.00), and the `DRConfig` demand-response container. **DR is containers-only in v0** (architecture §2.4): `DRConfig` loads a DR file and the internal `_build_dr` hook is a no-op — supplying a DR file never changes the objective. EECO reasons in naive local wall-clock time; tz-aware indices are rejected at the wrapper boundary with `FlexDataError`. New costing reference page (`docs/reference/flexops/costing.rst`) and numpy intersphinx mapping (M06).
- `flexops.costing.add_operating_cost` is now the facility-level umbrella that builds the **whole** in-objective operating cost — electricity **and** gas — onto one opex block, returning a single `OperatingCostHandles` whose `total_operating_cost` is the sum across utilities (EECO namespaces its Pyomo components by utility, so `electric_*`/`gas_*` never collide on one block). It reads the facility consumption from the standard series on the block (`block.power_electrical`, `block.gas_usage`) when not passed, with `electrical_power=`/`gas_power=` overrides; a utility whose series is neither passed nor present is omitted, and it raises `FlexConfigError` if neither resolves. The former electric-only `add_operating_cost` is renamed `add_electricity_cost` (still exported) and, with `add_gas_cost`, remains the single-utility builder. **Deviation from the M06 spec:** the spec names `add_operating_cost` as the electric-only bridge; this session renames that to `add_electricity_cost` and repurposes `add_operating_cost` as the combined electric+gas umbrella, folding facility-level aggregation (nominally M07 FlexCosting territory) into M06 at the user's request. The gas-consumption block attribute name `gas_usage` is a local convention (no `flexcore.nomenclature` entry in v0; it is a gas-usage series in EECO's units, not a `power_thermal` kW duty).
- `Pump` gains a `power_relation` config option (`"constant_intensity"`, the default, or `"hydraulic"`): the hydraulic relation adds a `delta_pressure[t]` `Var` tied to the inlet/outlet pressure states by the `pressure_change` equality constraint (`delta_pressure[t] == outlet_state.pressure[t] - inlet_state.pressure[t]`), requiring a `property_package` built with `has_pressure=True`, and excludes `pressure` from the inherited inlet-to-outlet bypass (a pump raises pressure rather than passing it through); both `inlet_state.pressure`/`outlet_state.pressure` are registered as IO inputs (fixed boundary conditions, like dispatch flow). Adds a mutable `efficiency` Var (dimensionless, bounded `[0, 1]`, default 0.7, fixed at build), and builds `power_electrical[t] = delta_pressure[t] * inlet flow / efficiency` in place of the constant-energy-intensity law. Patch to M04's `Pump`, deferred at the time for simplicity.

### Changed

- `flexops/costing/opex.py` now sources its rate_data column names, charge-column names, and the `electric`/`gas`/`energy` sentinels from `eeco.costs`' own string constants (`UTILITY`, `TYPE`, `CHARGE_METRIC`, `ELECTRIC`, `ENERGY`, …) instead of hardcoded literals, so an upstream EECO column rename tracks automatically rather than silently breaking tariff validation. Which columns flex-pse *requires* stays flex-pse's choice; only the string values are borrowed. A `unit` test guards that the tuples equal EECO's constants (M06).
- Install pipeline is now conda-only: `uv` is removed and `environment.yml` installs the editable package and its Python dependencies (including the pip-only `eeco`) through a `pip:` subsection, so `conda env create -f environment.yml` is the single install command. README, `PLAN.md`, and the M00 milestone spec updated accordingly.

### Added

- Project scaffold: four-package `src/` layout (`flexcore`, `flexops`, `flexparameterize`, `flexschedule`), import-linter DAG contract, pytest tier markers with collection-time enforcement, and CI skeleton (M00).
- Exception hierarchy; pinned idaes-pse/pyomo versions (M01).
- Added `TimeBlock`: the discrete-time substrate (ordered integer `time_index` set, `time` Param of elapsed `i*dt` in the user's units, unit-carrying `dt`, datetime↔index utilities, rolling-horizon initial-state registry and window metadata); a configurable `max_length` (dateutil `relativedelta`, default one calendar month) bounding the horizon; minimal Sphinx docs skeleton (M02).
- CI `standard-install` job (committed but commented out, pending the repo going public): remote-only install from the git ref (`pip install "git+<repo>@<ref>"`, no checkout) matrixed over Python 3.11–3.14 that imports every subpackage from a scratch dir, catching subpackages missing from the built distribution — or files left uncommitted — that the editable dev install would mask (M00).
- Added `flexcore.solvers`: a model classifier (`classify`/`ProblemClass`), a capability-matrix registry with cached availability probing (`available_solvers`), and the `get_solver`/`SolverFacade` facade that selects a solver by problem class and errors loudly (decision R5) when no capable solver is installed. Default open-source stack: HiGHS for LP, **SCIP for MILP and MINLP** (preferred over HiGHS for MILP; added to `environment.yml`), and IPOPT for NLP — built from idaes (HSL `ma27` linear solver) when idaes is importable, falling back to stock `SolverFactory` IPOPT (MUMPS) otherwise. When no MINLP-capable solver is installed, MINLP still raises pointing at `flexschedule.SolveSequence`. SCIP's dynamic-library path is isolated at invocation so it does not clash with idaes's bundled `libipopt`. The root `conftest.py` now forbids solver invocation and network access under `-m unit` and skips `needs_*`-marked tests via the registry; adds a `flexcore` reference page and a relaxation-policies explanation page (M05).
- Added the `OpsBlock` base of every flex-pse unit model (`flexops.core.ops_block`, inheriting IDAES `UnitModelBlockData` with no ControlVolumes, decision R1): the registration API (`register_io_variable`/`register_process_parameter`/`register_power`), base-provided `power_electrical`/`power_thermal` kW Vars via `declare_power`, the external-dispatch (DERMS) hook `set_external_dispatch`, the validated-only config slots (`unit_commitment`, `relaxation`, `allow_bypass`, `external_dispatch`; their constraints land in M08), and an M09-deferred `build_from_config` stub. `register_power`/`declare_power` require a `flexcore.nomenclature.PowerKind` member for `kind` (plain strings are rejected), and call sites import the nomenclature module as `nm` so constants like `nm.POWER_ELECTRICAL` read unambiguously as string names. Added the in-place update hook `update_parameters(values)` (`set_value` on registered mutable params, driven by FlexParameterize in M10): flex-pse never deletes model components — deletion leaves stale references in anything that captured the old component — so the earlier delete-and-rewire `replace_unit` helper was dropped in favor of it (conventions §9). Registration records and model-wide discovery live in `flexops.core.registration` (`IORegistry`, `iter_io_registry`). Added the `add_stream_ports` helper: it builds a single scalar inlet/outlet state block per stream from the configured `property_package` (state variables indexed over time), registers each side's volumetric flow (`flow_vol_phase`) as an input/output IO variable via a time-indexed `Reference`, and exposes the `inlet`/`outlet` ports through the inherited IDAES `add_inlet_port`/`add_outlet_port` (M03).
- New `model_and_block_structure` explanation page: defines the ConcreteModel/`TimeBlock`/`OpsBlock`/property-package block hierarchy and the variable-indexing convention (operational Vars indexed over `time_index`; property state variables carry the time index themselves on a single scalar state block per stream), plus the extensive/intensive arc split.
- Added `SimpleAqueousFlow`: the minimal IDAES property package whose state block carries a `flow_vol_phase` indexed by time then phase (single `Liq`), and a time-indexed `dens_mass` state variable (fixed at the configured `density` by default, free with `fixed_density=False`), plus opt-in `pressure`/`temperature`. State variables are indexed over time directly — extensive per-phase quantities lead with time then phase, intensive stream properties (`dens_mass`/`pressure`/`temperature`) drop the phase index — and the owning unit passes the time set via a `time_index` state-block config option, yielding one scalar state block per stream; exported from `flexops` (M03).
- Added `SimpleGasFlow`: the gas-phase counterpart of `SimpleAqueousFlow` whose state block always carries a `flow_vol_phase` (indexed by time then the single `Vap` phase), plus time-indexed `dens_mass`, `pressure`, and `temperature` (gas density varies with pressure/temperature; no equation of state is imposed). Exported from `flexops`, alongside a new top-level `PowerKind` re-export so the standardized power-kind names (`PowerKind.ELECTRICAL`/`PowerKind.THERMAL`) are importable directly from `flexops` (M03).
- Added the full versioned config schema (`flexcore.config.schema`, pydantic v2, decision R3): `IOVariableSpec`, `SurrogateSpec`, `ExternalDispatchSpec`, `UnitCommitmentConfig`, `UnitConfig`, `PlantConfig`, `NetworkConfig`, `TimeConfig`, `CostingConfig` (with a `DRConfig` container slot), and the top-level `ModelConfig` (mandatory semantic-version `schema_version`, exactly-one-of `network`/`plant`). Added `flexcore.config.io` (`load_model_config`/`dump_model_config` with JSON as the only on-disk format plus direct dict input, a `MIGRATIONS` table, and `export_json_schemas` with an optional `filename` for side-by-side schema versions) and the checked-in JSON Schema at `src/flexcore/config/schemas/model_config.schema.json`, whose descriptions are exported as plain single-line text (no newlines or section-sign codes; wrapping is the doc builder's job). Added `flexcore.nomenclature` (the `POWER_ELECTRICAL`/`POWER_THERMAL` constants and `PowerKind`). New docs: config-schema and energy-nomenclature explanation pages, `flexcore` config/nomenclature/exceptions reference sections, and a `flexops.properties` reference page (M03).

- Added the public, shipped `flexops.testing.UnitModelTestHarness`: every unit-model milestone (and any user writing a custom unit model) subclasses it instead of hand-writing the build/units-consistency/registration/energy-naming/degrees-of-freedom/solve/solution checks (`test_build`, `test_units_consistent`, `test_io_registration`, `test_energy_naming`, `test_dof` on the `unit` tier; `test_solve`, `test_solution` on the `component` tier, skipping cleanly if `flexcore.solvers.get_solver` is unavailable). Added `flexops.testing.dummy_time_block(n=3)`, a throwaway `TimeBlock` + `SimpleAqueousFlow` model reused by the M14 docs generator. Added `OpsBlockData.add_bypass_constraints(inlet, outlet, *, exclude_vars=())`: a generic inlet-to-outlet pass-through for every non-excluded, non-fixed state variable (e.g. `dens_mass` under `fixed_density` is skipped automatically), gated by `self.config.allow_bypass`; it resolves each port's sibling `"{port}_state"` block rather than the port's own `vars` mapping, since the latter are auto-generated `Reference`s carrying a leaky extra `UnindexedComponent_set` dimension. Added `SISOBlock` (`flexops.unit_models.base`), the first IO-topology base class (architecture §3.4/R6): builds the inlet/outlet ports via the inherited `add_stream_ports`, then its per-stream pass-through via `add_bypass_constraints` with no exclusions (flow's pass-through is itself a bypass equality, named `bypass_flow_vol_phase_eq`); `SISOBlock` overrides the inherited `allow_bypass` default to `True` so the topology is well-posed out of the box. Added `SimpleAqueousFlow.get_flow_basis_var_name()`/`SimpleGasFlow.get_flow_basis_var_name()` (both return `"flow_vol_phase"`), letting callers exclude "the flow" from a generic pass-through without hardcoding a property-package-specific name. Added the first two physical unit models on top of the SISO base: `Pump(SISOBlock)` (`power_electrical[t] = energy_intensity * inlet flow`, dimensionally exact kWh/m³ × m³/hr = kW; carries a `.. todo::` note for a future detailed power law, e.g. density·flowrate·head/efficiency, not built here) and `StorageTank(SISOBlock)` (holdup difference equation `volume[t+1] = volume[t] + dt*(in - out)` over `t = 0..N-2`, converting the whole flow-difference expression rather than assuming the flow basis's units). `StorageTank` now distinguishes `max_volume` (the maximum *possible* tank volume -- fixed by prior investment or space constraints, a static upper bound) from `capacity` (the *chosen* volume, a fixable design `Var` now bounded `(min_volume, max_volume)` so a design-mode solve can never exceed the maximum possible size). Added a bounded `level[t]` Var (`level_min`/`level_max` config, default `(0.0, 1.0)`) defined by `level_definition[t]: volume[t] == level[t] * capacity` -- the fractional fill relative to the *chosen* capacity, preventing the tank from draining all the way down or overfilling; this is linear (LP) in operations mode (`capacity` fixed) but bilinear (**NLP**) in design mode (`capacity` free), so design-mode solves of a model containing a tank need IPOPT or a `flexschedule.SolveSequence`, not HiGHS. `StorageTank` forces `unit_commitment.status = False` regardless of what a caller passes -- a tank has no on/off status, the canonical example of a physical subclass turning off a base capability (R6). New docs: `flexops.testing` and `flexops.unit_models` (with the `unit_model.rst` autosummary template, a `flexops-unit-tables` TODO placeholder for M14) reference pages (M04).

### Fixed

- `OpsBlock` now coerces an explicit `unit_commitment=None` to an all-defaults `UnitCommitmentConfig` in `build()` (Pyomo skips `ConfigValue` domains for `None`, so the domain-level coercion never ran).
