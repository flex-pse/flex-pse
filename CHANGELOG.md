# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed

- Install pipeline is now conda-only: `uv` is removed and `environment.yml` installs the editable package and its Python dependencies (including the pip-only `eeco`) through a `pip:` subsection, so `conda env create -f environment.yml` is the single install command. README, `PLAN.md`, and the M00 milestone spec updated accordingly.

### Added

- Project scaffold: four-package `src/` layout (`flexcore`, `flexops`, `flexparameterize`, `flexschedule`), import-linter DAG contract, pytest tier markers with collection-time enforcement, and CI skeleton (M00).
- Exception hierarchy; pinned idaes-pse/pyomo versions (M01).
- Added `TimeBlock`: the discrete-time substrate (ordered integer `time_index` set, `time` Param of elapsed `i*dt` in the user's units, unit-carrying `dt`, datetime↔index utilities, rolling-horizon initial-state registry and window metadata); a configurable `max_length` (dateutil `relativedelta`, default one calendar month) bounding the horizon; minimal Sphinx docs skeleton (M02).
- CI `standard-install` job (committed but commented out, pending the repo going public): remote-only install from the git ref (`pip install "git+<repo>@<ref>"`, no checkout) matrixed over Python 3.11–3.14 that imports every subpackage from a scratch dir, catching subpackages missing from the built distribution — or files left uncommitted — that the editable dev install would mask (M00).
- Added `flexcore.solvers`: a model classifier (`classify`/`ProblemClass`), a capability-matrix registry with cached availability probing (`available_solvers`), and the `get_solver`/`SolverFacade` facade that selects a solver by problem class and errors loudly (decision R5) when no capable solver is installed. Default open-source stack: HiGHS for LP, **SCIP for MILP and MINLP** (preferred over HiGHS for MILP; added to `environment.yml`), and IPOPT for NLP — built from idaes (HSL `ma27` linear solver) when idaes is importable, falling back to stock `SolverFactory` IPOPT (MUMPS) otherwise. When no MINLP-capable solver is installed, MINLP still raises pointing at `flexschedule.SolveSequence`. SCIP's dynamic-library path is isolated at invocation so it does not clash with idaes's bundled `libipopt`. The root `conftest.py` now forbids solver invocation and network access under `-m unit` and skips `needs_*`-marked tests via the registry; adds a `flexcore` reference page and a relaxation-policies explanation page (M05).
- Added the `OpsBlock` base of every flex-pse unit model (`flexops.core.ops_block`, inheriting IDAES `UnitModelBlockData` with no ControlVolumes, decision R1): the registration API (`register_io_variable`/`register_process_parameter`/`register_power`), base-provided `electrical_power`/`thermal_power` kW Vars via `declare_power`, the external-dispatch (DERMS) hook `set_external_dispatch`, the validated-only config slots (`unit_commitment`, `relaxation`, `allow_bypass`, `external_dispatch`; their constraints land in M08), and an M09-deferred `from_config` stub. Added the in-place update hook `update_parameters(values)` (`set_value` on registered mutable params, driven by FlexParameterize in M10): flex-pse never deletes model components — deletion leaves stale references in anything that captured the old component — so the earlier delete-and-rewire `replace_unit` helper was dropped in favor of it (conventions §9). Registration records and model-wide discovery live in `flexops.core.registration` (`IORegistry`, `iter_io_registry`) (M03).
- Added `SimpleAqueousFlow`: the minimal flow-only IDAES property package (volumetric `flow_vol`, optional fixed density), exported from `flexops` (M03).
- Added `SimpleGasFlow`: the gas-phase counterpart of `SimpleAqueousFlow` whose state blocks always carry `flow_vol`, `dens_mass`, `pressure`, and `temperature` (gas density varies with pressure/temperature; no equation of state is imposed). Exported from `flexops`, alongside a new top-level `PowerKind` re-export so the standardized power-kind names (`PowerKind.ELECTRICAL`/`PowerKind.THERMAL`) are importable directly from `flexops` (M03).
- Added the full versioned config schema (`flexcore.config.schema`, pydantic v2, decision R3): `IOVariableSpec`, `SurrogateSpec`, `ExternalDispatchSpec`, `UnitCommitmentConfig`, `UnitConfig`, `PlantConfig`, `NetworkConfig`, `TimeConfig`, `CostingConfig` (with a `DRConfig` container slot), and the top-level `ModelConfig` (mandatory `schema_version`, exactly-one-of `network`/`plant`). Added `flexcore.config.io` (`load_model_config`/`dump_model_config` with YAML canonical + JSON accepted, a `MIGRATIONS` table, and `export_json_schemas`) and the checked-in JSON Schema at `src/flexcore/config/schemas/model_config.schema.json`. Added `flexcore.nomenclature` (the `ELECTRICAL_POWER`/`THERMAL_POWER` constants and `PowerKind`). New docs: config-schema and energy-nomenclature explanation pages, `flexcore` config/nomenclature/exceptions reference sections, and a `flexops.properties` reference page (M03).
