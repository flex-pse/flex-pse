flexcore¶

Shared substrate for the flex-pse tools: the exception hierarchy, the solver facade, and (later) the versioned config schema.

Solvers¶

The solver layer classifies a model, detects which solvers are installed, and selects one — erroring loudly rather than transforming the model (decision R5; see Relaxation policies).

flexcore.solvers.get_solver(model: ConcreteModel | None = None, problem_class: ProblemClass | None = None, prefer: str | None = None) → SolverFacade¶

Select the best available solver for a problem class.

Exactly one of model or problem_class may be given. If model is given it is classified via classify(); if neither is given the class defaults to ProblemClass.LP (smallest choice, implementer’s). Candidate order is prefer (if named and capable) then the fixed priority list ["gurobi", "scip", "highs", "cbc", "ipopt"]. If prefer is named but unavailable or incapable, a warning is logged and selection falls through to the priority list. SCIP is tried before HiGHS, so MILP routes to SCIP when installed (benchmark-preferred); pure LP still routes to HiGHS since SCIP is not LP-capable. In particular MINLP routes to SCIP (the default open-source MINLP solver) when it is installed; only when no MINLP-capable solver is available does MINLP raise.

Parameters:

  • model – A Pyomo model to classify; mutually exclusive with problem_class.

  • problem_class – The ProblemClass to solve; mutually exclusive with model.

  • prefer – A solver name to try first.

Returns:

A SolverFacade bound to the chosen solver.

Raises:

  • ValueError – If both model and problem_class are given.

  • FlexSolverError – If no available solver supports the problem class. For MINLP the message points at flexschedule.SolveSequence; the facade never relaxes integrality itself.

Example

>>> from flexcore.solvers import get_solver, ProblemClass
>>> solver = get_solver(problem_class=ProblemClass.LP)
>>> results = solver.solve(model)

flexcore.solvers.classify(model: ConcreteModel) → ProblemClass¶

Classify a Pyomo model into a ProblemClass.

Only active constraints and the active objective are considered; inactive constraints, objectives, and blocks are ignored. A variable counts as discrete only if it is binary or integer and not fixed — so an LP with fixed binaries classifies LP. Note that a quadratic constraint classifies NLP, not QP: only a quadratic objective over all-linear constraints is QP (smallest choice consistent with the QP capability matrix).

Parameters:

model – A constructed Pyomo model to classify.

Returns:

The problem class. Never returns MINLP_OA/MINLP_TR (reserved).

Example

>>> import pyomo.environ as pyo
>>> from flexcore.solvers import classify, ProblemClass
>>> m = pyo.ConcreteModel()
>>> m.x = pyo.Var()
>>> m.c = pyo.Constraint(expr=m.x <= 1)
>>> m.obj = pyo.Objective(expr=m.x)
>>> classify(m) is ProblemClass.LP
True
class flexcore.solvers.ProblemClass(*values)¶

Mathematical program classes that the solver facade reasons about.

LP/QP/MILP/NLP/MINLP are the classes classify() can return. MINLP_OA (outer approximation) and MINLP_TR (trust region) are reserved strategy slots — deliberately unimplemented in v0 and never returned by classify().

flexcore.solvers.available_solvers() → dict[str, set[ProblemClass]]¶

Return the capability matrix restricted to installed solvers.

Returns:

A dict mapping each installed solver name to its capability set — the subset of CAPABILITIES whose solver probes as available.

Capability matrix¶

available_solvers() returns the subset of this matrix whose solver is installed. The matrix is a plain module constant (flexcore.solvers.registry.CAPABILITIES) and is extensible — a user may register an additional solver entry before calling get_solver().

Solver

Supported problem classes

highs

LP, MILP

cbc

LP, MILP

ipopt

NLP (built from idaes with HSL ma27 when available, else stock IPOPT)

scip

MILP, MINLP (preferred over HiGHS for MILP; the default open-source MINLP solver)

gurobi

LP, QP, MILP

Config schema¶

The versioned, JSON-canonical config the whole model+run is built from (decision R3; see The config schema). Pydantic is the schema authority; CURRENT_SCHEMA_VERSION tags what this build writes.

ModelConfig

The top-level config artifact the whole model and run are built from.

NetworkConfig

A named collection of plants and the inter-plant arcs between them.

PlantConfig

A named collection of unit models and the arcs between them.

UnitConfig

A single unit model: its class, construction options, and IO/logic.

IOVariableSpec

A declared process input or output variable of a unit.

SurrogateSpec

A fitted (or default) energy/IO relationship for a unit.

SurrogateType

Which predefined surrogate class a SurrogateSpec's data describes.

ExternalDispatchSpec

Declares an external (DERMS) command source for a controllable variable.

UnitCommitmentConfig

Per-unit unit-commitment configuration, a validated container.

ArcSpec

A directed connection between two unit (or plant) ports.

TimeConfig

The discrete-time horizon specification.

CostingConfig

Tariff, price, demand-response, and solve/objective options for a run.

PriceSpec

A native price for one energy carrier or fuel: a number and its units.

DRConfig

Demand-response container slot, a placeholder in v0: DR containers exist so wiring is stable, but no DR constraints are built.

Config I/O¶

flexcore.config.io.load_model_config(source) → ModelConfig¶

Load and validate a config file or dict into a model config.

Any unit surrogate naming a source sidecar is filled in here, at the config boundary, so nothing downstream sees a half-loaded relationship. A relative source resolves against the config file’s own directory, or the working directory when the config came in as a dict.

Parameters:

source – Path to a .json config file, or an already-parsed config mapping (which is not mutated).

Returns:

The validated ModelConfig.

Raises:

FlexConfigError – If the format is unsupported, schema_version is missing, malformed, or newer than this build, a migration step is missing, the config fails validation (the message names the bad field path), or a surrogate source cannot be loaded.

flexcore.config.io.load_surrogate_source(spec: SurrogateSpec, base_dir=None) → SurrogateSpec¶

Fill a surrogate in from the sidecar file its source names.

Lets a relationship live beside the config rather than inside it — a fitted curve with hundreds of terms, or one a tool wrote separately. The file is a JSON object holding data, in the shape surrogate_type’s class expects; it replaces what the spec wrote inline. source is kept on the result, so the config still points at where the relationship came from.

Parameters:

  • spec – The SurrogateSpec to fill in; returned unchanged when it names no source. Never mutated.

  • base_dir – Directory a relative source resolves against (the directory of the config file that named it). None resolves against the current working directory.

Returns:

A filled-in copy of spec.

Raises:

FlexConfigError – If the source is not a readable .json file, is not a JSON object, carries a key that is not a surrogate field, or supplies a value that fails validation.

flexcore.config.io.MIGRATIONS: dict[str, Callable[[dict], dict]] = {'0.0.1': <function _to_0_0_2>, '0.0.2': <function _to_0_0_3>}¶

flexcore.config.io.export_json_schemas(directory, filename: str = 'model_config.schema.json') → None¶

Write the exported JSON Schema for the model config to directory.

Serializes ModelConfig’s JSON Schema with indent=2 and sort_keys=True so the checked-in schema diffs only on real schema changes (pitfall 7). Descriptions are collapsed to single-line plain text — line wrapping is the documentation builder’s job, not the schema’s. Run once and commit the result to src/flexcore/config/schemas/.

Parameters:

  • directory – Destination directory for the schema file.

  • filename – Output filename; override it to keep schemas for several versions side by side in one directory.

class flexcore.nomenclature.PowerKind(*values)¶

The kinds of power draw a unit can declare.

Each member’s value is the kind string accepted by register_power and declare_power and stored on an flexops.core.registration.PowerRecord. Fuel is absent by design — it is a volumetric flow (FUEL_USAGE), not a power.

Exceptions¶

exception flexcore.exceptions.FlexError¶

Base class for all flex-pse errors.

Catch this to handle any flex-pse-specific failure regardless of category. Prefer raising one of the concrete subclasses below over this base class directly, so callers can distinguish failure categories.

exception flexcore.exceptions.FlexConfigError(message: str, *, field: str | None = None, value: object = None)¶

Raised when persisted or runtime configuration is invalid.

Raise this for malformed or missing configuration: a pydantic config file that fails validation, a Pyomo ConfigDict entry given an invalid value, or a config referencing a field/unit/tag that does not exist. The message must name the exact field that was wrong and what value would fix it.

field¶

Dotted name of the config field, unit, or tag that was invalid, if known.

value¶

The invalid value that was supplied, if known.

exception flexcore.exceptions.FlexSolverError(message: str, *, solver: str | None = None, problem_class: str | None = None)¶

Raised when a solver cannot be found, is unsupported, or fails to run.

Raise this when the solver facade cannot satisfy a request: the named solver is not installed, no available solver supports the model’s classification (e.g. NLP vs. MILP), or the solver process itself errors out before returning a status. The message must tell the user which solver was requested and how to install or substitute one.

solver¶

Name of the solver that was requested or attempted, if known.

problem_class¶

Name of the problem classification (e.g. "MINLP") the solver needed to support, if known.

exception flexcore.exceptions.FlexDataError(message: str, *, field: str | None = None)¶

Raised when input plant/historian data is missing or insufficient.

Raise this for problems with data supplied to FlexParameterize or FlexOps: missing historian tags, insufficient data to regress a parameter, or data that fails a sufficiency/validity check. The message must name the missing or invalid data and what additional data or action would resolve it.

field¶

Name of the missing or invalid historian tag or field, if known.

Logging¶

The shared logger for flex-pse. It provides a custom level for configuration simplifications, plus optional deduplication of INFO and WARNING records emitted from the same call site within a sliding window.

flexcore.logger.CONFIGURATION_SIMPLIFICATIONS = 21¶

Convert a number or string to an integer, or return 0 if no arguments are given. If x is a number, return x.__int__(). For floating-point numbers, this truncates towards zero.

If x is not a number or if base is given, then x must be a string, bytes, or bytearray instance representing an integer literal in the given base. The literal can be preceded by ‘+’ or ‘-’ and be surrounded by whitespace. The base defaults to 10. Valid bases are 0 and 2-36. Base 0 means to interpret the base from the string as an integer iteral. >>> int(‘0b100’, base=0) 4

Global configuration¶

Call set_global_level() and set_global_dedup_enabled() once at the start of a script to control the threshold and deduplication behavior for all loggers obtained afterward:

import logging
from flexcore.logger import get_logger, set_global_level, set_global_dedup_enabled

set_global_level(logging.WARNING)
set_global_dedup_enabled({
    logging.WARNING: True,
    logging.INFO: True,
})

# import additional flex-pse modules here, they will use above defaults
_log = get_logger(__name__)

Available levels (lowest to highest):

  • logging.DEBUG (10)

  • logging.INFO (20)

  • CONFIGURATION_SIMPLIFICATIONS (21)

  • logging.WARNING (30)

  • logging.ERROR (40)

  • logging.CRITICAL (50)

The default threshold is CONFIGURATION_SIMPLIFICATIONS. Deduplication is a per-level toggle; by default it is enabled for WARNING and CONFIGURATION_SIMPLIFICATIONS.
