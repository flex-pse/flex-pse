# M10 — FlexParameterize core (2-way)

**Effort:** 3 days · **Depends on:** M09 · **Parallelizable:** with M12

## Goal
Stand up the FlexParameterize pipeline end to end for the simplest regressor,
**in both directions** (architecture §5, R10/R11): tabular data → tag aliasing
(`TagMap`) → sufficiency validation (`check_sufficiency`) → constant-intensity
fit → **either** an emitted `ModelConfig` **or** an in-place mutation of a LIVE
FlexOps model. The two directions must agree:

- **Emit direction** — the round-trip invariant (architecture §5): a config
  emitted from data generated by a known Pump rebuilds a model whose coefficient
  matches the truth to 1e-6.
- **Apply direction** — `apply.py`'s `apply_to_model(model, data, tagmap)` takes
  a built FlexOps model, matches data streams to its registered parameters, and
  **mutates the model**: it fixes regressed parameters in place and, where the
  fit warrants a richer relationship than the unit's default constant intensity,
  **swaps the unit's energy-relationship Constraint in place** — deactivate the
  default `electrical_work_relation` (M09) and attach a new equality Constraint
  built from the fitted `SurrogateSpec`, on the same unit object, same ports and
  arcs (R11; no block replacement, nothing to reconnect).

The invariant tying them together (architecture §5, R10): the in-place
`apply_to_model` result matches the emitted-config rebuild — the two directions
produce the same behavior.

## Specification

### TagMap (`src/flexparameterize/tags.py`)
```python
class TagMap:
    def __init__(self, mapping: dict[str, str]): ...          # tag -> "plant.unit.variable" alias
    @classmethod
    def from_file(cls, path) -> "TagMap": ...                 # JSON always; YAML if pyyaml importable
    def apply(self, df: pd.DataFrame) -> pd.DataFrame: ...    # returns a RENAMED COPY
    def report_unmapped(self, df: pd.DataFrame) -> "TagReport": ...
```
- Aliases are dotted `plant.unit.variable` strings (architecture §5). Keys are raw
  historian tags (arbitrary strings like `"PIT-101.PV"`).
- `apply` renames matching columns and leaves the rest untouched (extra columns
  are legal — sufficiency decides what matters). It never mutates the input.
- `report_unmapped(df)` returns a small dataclass `TagReport` (implementer's
  choice of fields; minimum: `unmapped_columns: list[str]` and
  `suggestions: dict[str, list[str]]`) where suggestions come from
  `difflib.get_close_matches(column, known_tags, n=3)` — stdlib only, **no new
  dependencies**. Give it a readable `__str__` for log/error output.
- `from_file`: JSON via stdlib; for `.yaml`/`.yml` try `import yaml` and raise
  `FlexConfigError` with install instructions if absent (implementer's choice —
  pyyaml must not become a hard dependency). Validate the loaded object is a flat
  `dict[str, str]`; anything else → `FlexConfigError` naming the bad key.
- Duplicate targets (two tags → one alias) → `FlexConfigError` at construction.

### check_sufficiency (`src/flexparameterize/validate.py`)
```python
def check_sufficiency(
    registry, data: pd.DataFrame, time_block=None
) -> SufficiencyReport: ...
```
- `registry` accepts either an `IORegistry` or a built model (in which case walk
  it with `iter_io_registry(model)` — support both, it is one `isinstance`).
- `SufficiencyReport` is a dataclass listing, **per registered IO pair** (a unit's
  set of registered input/output variables — multiple valid IO pairs per unit are
  supported and each is checked):
  - unit name, variable names in the pair;
  - present vs. missing columns (matched by the dotted alias);
  - non-null row count per present column (and a minimum-rows check —
    implementer's choice of default threshold, e.g. 10; make it a keyword);
  - time-index alignment: when `time_block` is given, compare `data.index`
    against `time_block.datetime_index` (dtype is datetime, monotonic, within
    range; exact-grid match not required in v0 — implementer's choice, document);
  - property `sufficient: bool` — True iff every pair has all columns present,
    enough non-null rows, and an aligned index.
- Report objects must render actionably (`__str__` tables listing what is missing
  and what to do — conventions §3 error style). Insufficient data does NOT raise;
  callers branch on `.sufficient` (raising is the caller's choice).
- The module docstring (and `check_sufficiency` docstring) must define
  **zero-degree-of-freedom regression** exactly as architecture §5 does: "the
  registered IO pairs exactly determine the regression problem — no unmapped
  inputs, no free parameters after fit."

### ConstantIntensityRegressor (`src/flexparameterize/regression/constant.py`)
Fits the mean energy intensity from paired (flow, power) series:
```python
class ConstantIntensityRegressor:
    def fit(self, X: pd.DataFrame, y: pd.DataFrame): ...   # X: one flow column; y: one power column
    def to_surrogate_spec(self) -> SurrogateSpec: ...
```
- Fit rule: drop rows where either side is null or flow == 0, then
  `intensity = mean(power / flow)` (implementer's choice vs. least squares —
  document the choice in the docstring; the round-trip test only needs
  exact recovery on noise-free data).
- Store fit results on the instance: the coefficient, `n_samples`, metrics
  (`r2`, `rmse` computed against `intensity * flow`), and the data window
  (`(index.min(), index.max())`). M11 formalizes this as `FitResult`; shape your
  attributes so that refactor is mechanical (it will say so).
- `to_surrogate_spec()` returns a `SurrogateSpec` with functional form
  `constant_intensity`, the coefficient, and input/output variable names taken
  from the fitted columns.

### emit_model_config (`src/flexparameterize/emit.py`)
```python
def emit_model_config(unit_or_class, fit_result, provenance) -> ModelConfig: ...
```
- `unit_or_class`: a built OpsBlock unit (read its class name + `IORegistry`) or
  a unit-model class (read class name; IO specs then come from the fit result's
  column names) — support both.
- Assembles a full `ModelConfig`: `schema_version`, unit-model class name,
  construction options, `IOVariableSpec` list, `SurrogateSpec` from the
  regressor, and `provenance` containing at minimum: fit metrics, data window,
  and package versions (`flex-pse`, `pyomo`, `pandas` — via
  `importlib.metadata.version`; implementer's choice of exact key names, but
  they are part of the emitted file, so document them).
- Serialization is NOT reimplemented here: callers persist with
  `flexcore.config.io.dump_model_config(cfg, path)`.

### apply_to_model (`src/flexparameterize/apply.py`) — the mutate-in-place direction
```python
def apply_to_model(model, data: pd.DataFrame, tagmap: TagMap) -> ApplyReport: ...
```
This is the **FlexParameterize → FlexOps** direction of the two-way coupling
(architecture §5, R10). Given a **LIVE built FlexOps model**, tabular data, and a
`TagMap`, it fits each registered unit and **mutates the model in place** — no
config file is written. Per unit:
- **(a) Fix regressed parameters in place.** Alias the data (`tagmap.apply`),
  fit the registered parameters exactly as the emit path does (reuse the same
  `ConstantIntensityRegressor`), and `.fix()` each regressed
  `register_process_parameter` on the live model to its fitted value. This drops
  the model's degrees of freedom (the parameters that were free before are now
  fixed data-derived constants).
- **(b) Swap the energy-relationship constraint in place.** Where the fit
  warrants a richer relationship than the unit's default constant intensity,
  deactivate the unit's `electrical_work_relation` Constraint (M09's documented
  swap contract, R11) and attach a new equality Constraint built from the fitted
  `SurrogateSpec` (`output[t] == intercept + sum(coef_i * input_i[t])`), reusing
  the unit's existing registered IO Vars — same unit object, same ports/arcs, no
  reconnection. FlexOps provides the named Constraint to swap (M09); this
  milestone drives the swap, it does not reimplement block/port machinery.
- Reuse: `apply_to_model` shares the fit machinery and the `SurrogateSpec`
  construction with `emit.py` — same fit, two consumers. Do not fork the
  regression logic.
- `ApplyReport` (dataclass, implementer's choice of fields; minimum: which units
  had parameters fixed, which had blocks replaced, DOF before/after) renders
  actionably like the other reports.
- Insufficient data: call `check_sufficiency` first and raise `FlexDataError`
  (actionable message) if not sufficient — `apply_to_model` mutates a real model,
  so it must not proceed on inadequate data (this is the caller-side raise the
  emit path leaves optional).

### The headline round-trip and the two-directions-agree invariant (component tests)
1. Build a `Pump` on a 100-step TimeBlock with a known `energy_intensity`.
2. Produce 100 steps of data by **direct evaluation** (fix a varying flow profile,
   compute power from the constraint relation — no solver needed; a solve is
   permitted but keep the test in the component budget).
3. Export a `flow`/`power` DataFrame indexed by `time_block.datetime_index`, then
   rename its columns to deliberately different historian-style tags
   (`"FT_0231.PV"`, `"MTR_KW_04"`).
4. `TagMap` maps them back → `check_sufficiency(...)` passes →
   `ConstantIntensityRegressor.fit` → `emit_model_config` →
   `dump_model_config` → `load_model_config` →
   rebuild via `ConstantEnergyIntensityModel.from_config`.
5. Assert the rebuilt model's intensity coefficient equals the known truth to
   `pytest.approx(rel=1e-6)`.

This is integration-adjacent but stays **component** tier: 100 steps, no solver
required, well under 30 s.

**The apply-direction and agreement checks** reuse the same fixture:
- Build a second identical live model, run `apply_to_model(model, data, tagmap)`,
  and assert (a) the regressed parameter is now **fixed** on the live model at the
  known truth (rel=1e-6) and its **DOF dropped**; (b) for a unit whose fit
  warranted a richer relationship, `apply_to_model` **deactivated the default
  `electrical_work_relation` Constraint and attached the new one** built from the
  fitted `SurrogateSpec` on the same unit object (assert the old Constraint is
  inactive, the new one is active, and the unit's ports/arcs are unchanged).
- The **two-directions-agree invariant**: the in-place `apply_to_model` result and
  the emitted-config rebuild describe the same behavior — assert the surrogate
  coefficient on the applied model equals the coefficient on the rebuilt model to
  rel=1e-6 (evaluate the two units' output-constraint bodies at a few probe
  points if you prefer a behavioral comparison; no solver needed).

## Pitfalls
1. **Mutating the caller's DataFrame.** `TagMap.apply` must return a copy;
   pandas `rename` already does — don't add `inplace=True`.
2. **Fuzzy matching pulling in new deps.** `difflib.get_close_matches` only. No
   rapidfuzz/thefuzz.
3. **Raising on insufficient data inside `check_sufficiency`.** It reports;
   callers decide. (The regressors in M11 will raise `FlexDataError` when handed
   insufficient data — different layer.)
4. **Division by zero in the constant fit.** Zero-flow rows must be dropped
   before `power/flow`; an all-zero-flow frame → `FlexDataError` with a message
   saying what to do.
5. **Provenance drift.** Versions must be read at emit time, not hardcoded;
   the JSON must still validate — provenance is part of `SurrogateSpec`'s schema
   (R3), not a free-form sidecar.
6. **Layer violation.** `flexparameterize` may import `flexops`/`flexcore` only;
   import-linter will fail the build otherwise (conventions §6).
7. **Datetime index assumptions.** Historian exports often have a plain column,
   not an index; v0 requires a `DatetimeIndex` and the sufficiency report must say
   exactly that when it is missing, not crash in pandas internals.
8. **Rebuilding ports/arcs during the swap.** The constraint swap touches only
   the named `electrical_work_relation` Constraint and the unit's existing
   registered IO Vars (architecture §5, R11) — `apply.py` must not delete/rebuild
   the unit block or its ports. Leaving the old Constraint active alongside the
   new one (double-counting the energy relation) is the classic bug — the apply
   test asserts the old Constraint is deactivated.
9. **Forking the fit logic between emit and apply.** Both directions must use the
   same regressor and the same `SurrogateSpec` construction — one fit, two
   consumers (emit → config, apply → live model). Divergence here is what the
   two-directions-agree invariant test guards.
10. **`apply_to_model` proceeding on insufficient data.** Unlike
    `check_sufficiency` (which only reports), `apply_to_model` mutates a real
    model and must raise `FlexDataError` up front when data is insufficient.
